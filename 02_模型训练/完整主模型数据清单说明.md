# 完整主模型 episode 清单与运行接口

实现：`echo.training.protocol_pipeline`；模型唯一入口：`echo.models.protocol.ProtocolECHO`。此处描述格式，不是已经放行的真实训练数据。

## 数据文件

每站一份预测输入 NPZ：真实节点 `weather_nodes[N,T,3]`、UTC步末 `time_ns`、节点属性、增量面积、拓扑、边属性及覆盖标记、16个河谷token及掩码、64维历史气候、许可 `support_h`。阶段A前可以没有参考Q；阶段A后由同一个运行器生成交叉拟合 `reference_q` 并接入，不用全零伪造参考。

输入必须有至少两个日历年的支持前气象。支持期前90天由同一成员参数产生Q并暖启动动态状态。气候截止时刻不得晚于该episode起报，逐站属性名、来源文件哈希、图/气象/地形语义写入独立provenance JSON。

来源标签 NPZ 与输入分离：`query_h` 和许可 `q_supervision`，Q长度等于支持＋查询；输入对象只含支持H。来源验证标签只含 `query_h`，没有Q。开发目标输入清单不能含标签路径；未来H保留在独立评分库。

清单结构：

```json
{
  "protocol": "ECHO_NatureWater_main_v1",
  "complete_spatial_inputs_verified": false,
  "forbidden_systems": [],
  "episodes": [
    {
      "station_id": "来源站号",
      "terminal_system_id": "固定终端水系",
      "role": "train",
      "crossfit_fold": 0,
      "input_path": "inputs/来源站号.npz",
      "input_path_sha256": "由真实文件计算",
      "provenance_path": "provenance/来源站号.json",
      "provenance_path_sha256": "由真实文件计算",
      "labels_path": "source_labels/来源站号.npz",
      "labels_path_sha256": "由真实文件计算",
      "support_start": 17544,
      "support_end": 17712,
      "query_end": 17880
    }
  ]
}
```

索引只是示意，不能照抄17544或设置标记绕过验收：偏移须从真实UTC日期计算，闰年按日历处理。初版运行器每个站一个固定episode，每个资料预算用独立运行清单、同一共享资料版本；它尚不是大规模随机episode采样与分桶加载器。正式服务器训练需要扩展采样层，不能把重复一个窗口的很多优化步称为覆盖了所有历史事件。

三折必须包含至少三个不同训练水系，整个水系的fold一致。按源站生成参考Q时，其前端训练清单不含该站整个相连水系。固定节点范围与参考水平由来源训练期参考Q确定。

## 角色与日期

- `train`：支持和查询均在2013-10-01（含）到2018-10-01（不含），监督Q只属于许可来源水系。
- `validation`：2018-10-01（含）到2019-10-01（不含），仅来源验证H决定停止、选参和残差校准；需要在这个水文年内安排支持/查询窗口。
- `development_test`：主支持2019-10-01到2020-10-01，未来检验2020-10-01到2021-10-01；这不是论文封存盲测。
- 封存盲测不由这个本地入口自动执行。

## 运行

资料生成并实际核验之后：

```powershell
& .\本地环境\python.exe -m echo.training.protocol_pipeline --index '完整空间episode清单.json' --check-only

# Windows可以先准备同一结构的A阶段；后续不自动换历史骨干
& .\本地环境\python.exe -m echo.training.protocol_pipeline --index '完整空间episode清单.json' --config '02_模型训练/完整主模型_本地与服务器.yaml' --output '本地运行/完整前端A_新版本' --stage-A-only
```

在Linux官方CUDA环境，使用同一数据格式与配置：

```bash
python -m echo.training.protocol_doctor --exercise --output 本地运行/官方骨干验收.json
python -m echo.training.protocol_pipeline --index 完整空间episode清单.json --config 02_模型训练/完整主模型_本地与服务器.yaml --output 本地运行/完整主链_新版本 --profile local
```

`--profile server`改变优化步数上限，B/C/D按来源验证停止。当前A阶段使用显式固定计算预算，不根据被排除fold的Q挑选前端；服务器正式A阶段的来源内部验证、随机episode分桶、大规模吞吐和断点续训尚需补齐。输出已保存阶段优化器和RNG状态，但当前入口尚不提供跨阶段自动恢复调度，不能把“保存检查点”与“自动续训已验收”混为一谈。

预测保存成员轨迹NPZ，分为联合成员本身的分歧与叠加来源AR(1)残差的总成员，分别生成`predictions`和`predictions_member_only`索引。两种索引接入同一个既有评分器与报告器，保证相同标签和事件规则；预测完成本身不表示统计报告已完成。

模型预测完成后，评分程序单独读取未来标签：

```bash
python -m echo evaluate --predictions 本地运行/完整主链_新版本/predictions --labels 独立评分标签目录 --output 本地运行/完整主链_新版本/evaluation_total
python -m echo evaluate --predictions 本地运行/完整主链_新版本/predictions_member_only --labels 独立评分标签目录 --output 本地运行/完整主链_新版本/evaluation_members
python -m echo report --evaluation 本地运行/完整主链_新版本/evaluation_total --predictions 本地运行/完整主链_新版本/predictions --labels 独立评分标签目录
```

标签为每站一个Parquet，仅评分器读取`time_ns`与`H`。评分记录预测、预测索引及标签哈希，成员区间/总区间分别评分，不能把残差带来的覆盖率变化混为地方后验本身的改进。
